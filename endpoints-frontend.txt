ENDPOINTS DETALLADOS PARA EL FRONTEND

1. NUEVO: Cancelar ausencia programada
POST /asistencia/ausencias-masivas/cancelar/:id

Headers:
  Content-Type: application/json
  user-id: string (UUID del usuario que cancela)

Parámetros de URL:
  id: string (UUID de la ausencia programada a cancelar)

Response 200:
{
  "success": true,
  "message": "Ausencia programada cancelada exitosamente",
  "data": {
    "cancelada": true
  },
  "timestamp": "2025-01-31T10:30:00.000Z"
}

Response 400:
{
  "success": false,
  "message": "El ID del usuario es obligatorio para cancelar ausencias",
  "error": "BAD_REQUEST",
  "statusCode": 400,
  "timestamp": "2025-01-31T10:30:00.000Z"
}

Response 404:
{
  "success": false,
  "message": "Ausencia programada no encontrada",
  "error": "NOT_FOUND",
  "statusCode": 404,
  "timestamp": "2025-01-31T10:30:00.000Z"
}

WEBSOCKET PARA NOTIFICACIONES EN TIEMPO REAL

Conectar a: ws://localhost:3000

Eventos de conexión:
1. Conectar:
   - URL: ws://localhost:3000
   - El servidor responde con evento 'connected'

2. Suscribirse a notificaciones globales:
   - Enviar: 42["subscribe_global"]
   - El servidor responde con evento 'subscribed_global'

3. Recibir notificaciones:
   - Evento: 'new_notification'
   - Datos: {
       "notificacion": {
         "id": "uuid",

RESUMEN DE CAMBIOS PARA EL FRONTEND:

ENDPOINTS QUE SIGUEN IGUAL:
- POST /asistencia/ausencias-masivas/ejecutar (sin cambios)

ENDPOINTS MODIFICADOS:
- POST /asistencia/ausencias-masivas/programar (agregar header user-id)
- GET /asistencia/ausencias-masivas/programadas (respuesta con info de usuario)

ENDPOINTS NUEVOS:
- POST /asistencia/ausencias-masivas/cancelar/:id
- GET /notificaciones
- PATCH /notificaciones/:id/marcar-leida
- GET /notificaciones/contador
- GET /notificaciones/test-gateway
- POST /notificaciones/test-scheduler

WEBSOCKET NUEVO:
- ws://localhost:3000 para notificaciones en tiempo real

NOTAS IMPORTANTES:
1. El header 'user-id' es OBLIGATORIO para programar y cancelar ausencias
2. Solo el usuario que programó una ausencia puede cancelarla
3. No se puede programar una nueva ausencia si ya hay una programada
4. Las notificaciones se envían automáticamente cuando el scheduler ejecuta
5. El WebSocket permite recibir notificaciones en tiempo real
6. Las notificaciones incluyen información personal del usuario (nombre y apellido)
